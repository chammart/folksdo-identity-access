Identity owns business semantics and lifecycle state. BetterAuth is used as an authentication-provider adapter and does not define the Identity Service business boundary.

Service Boundary

Identity Owns

  • Global user identity
  • Email verification lifecycle
  • User activation lifecycle
  • Authentication provider coordination
  • Session lifecycle creation and termination
  • Password reset lifecycle coordination
  • Credential lifecycle events
  • Identity business events
  • Identity outbox messages
  • Known external Identity facts required for Identity reactions

Identity Does Not Own

  • Tenant membership
  • Active tenant membership context
  • Authorization roles or permissions
  • Tenant provisioning
  • Subscription lifecycle
  • Billing state
  • Application business data

Invitation SignUp™

Invitation SignUp™ creates or reuses a global Identity when a person signs up through a valid invitation.

Request

POST /api/v1/identity/invitation-sign-up
Content-Type: application/json

{
  "invitationToken": "invite_abc123",
  "firstName": "John",
  "lastName": "Doe",
  "password": "StrongPassword123!"
}

Current Session™

Current Session™ resolves the caller's current authenticated session while hiding provider-specific authentication details from the public API.

Request

GET /api/v1/identity/session

Business Outcome

Authentication session resolved
Identity-owned session state returned
Provider-specific details remain encapsulated

Example Response

{
  "authenticated": true,
  "session": {
    "sessionId": "ses_001",
    "userId": "usr_sarah_001",
    "expiresAt": "2026-07-02T13:00:00.000Z"
  }
}

This query does not resolve Membership context and does not perform Access authorization decisions.

Change Password™

Change Password™ allows an already authenticated Identity to replace its current password while preserving the Identity business boundary around credential lifecycle and session semantics.

Request

POST /api/v1/identity/change-password
Content-Type: application/json

{
  "currentPassword": "StrongPassword123!",
  "newPassword": "NewStrongPassword456!"
}

Authentication Requirement

Active authenticated session required

Business Outcome

Current authenticated Identity resolved
Active session verified
Current credential validated through BetterAuth
New credential applied through BetterAuth
Credential lifecycle update recorded
identity.credential_updated event persisted
Matching outbox message persisted
Existing authenticated session preserved according to Identity session policy

Response

{
  "userId": "usr_sarah_001",
  "changedAt": "2026-08-09T00:00:00.000Z",
  "status": "updated"
}

Events

identity.credential_updated

Outbox Subjects

identity.credential_updated
Change Password™ is distinct from Reset Password™. Change Password™ requires an active authenticated session and knowledge of the current credential. Reset Password™ is a recovery flow driven by a password-reset token.

Error Model

  • Malformed requests return HTTP 400.
  • Missing or invalid authentication returns the appropriate authentication failure.
  • Invalid invitation tokens return stable semantic errors.
  • Invalid or expired verification tokens return stable semantic errors.
  • Invalid credentials return a stable authentication error.
  • Inactive, unverified, suspended, disabled, or archived identities cannot authenticate where prohibited by Identity rules.
  • Unknown or inactive sessions cannot be treated as active authenticated sessions.
  • Invalid or expired password-reset tokens are rejected through the Identity semantic boundary.
  • Change Password™ requires an active authenticated session.
  • An invalid current password is rejected without modifying the credential.
  • The replacement password must satisfy the configured credential policy.
  • Already-completed lifecycle transitions follow the current idempotency or semantic conflict rule defined by the use case.
  • Provider-specific BetterAuth failures are translated at the Identity boundary rather than leaked as provider contracts.
